## The project at a glance

The layoffs-tracker is a Next.js App Router application that aggregates tech layoff data. Users can browse companies, view layoff reports, read analysis articles, and (if paid) access premium content. It uses:

- **Next.js 14+ App Router** for routing and rendering
- **Prisma + PostgreSQL** for the database
- **NextAuth** for authentication
- **Stripe** for payments
- **Tailwind CSS** for styling
- **Vercel** for deployment

## Tracing a request: `/articles/big-tech-layoffs-2026`

Let's follow what happens when a user visits this URL:

**Step 1: Routing.** Next.js matches `/articles/[slug]/page.tsx`. The `slug` param is `"big-tech-layoffs-2026"`.

**Step 2: Server Component renders.** The page is a Server Component. It calls Prisma directly:

```tsx
const article = await prisma.article.findUnique({
  where: { slug: params.slug },
  include: { tags: true, layoffs: { include: { company: true } } },
});
```

**Step 3: Access check.** If the article is premium, the server checks if the user has a paid subscription. If not, it redirects to the paywall.

**Step 4: HTML response.** The server renders the full HTML — article title, body, related layoff data — and sends it to the browser. No loading spinner needed because data fetching happened on the server.

**Step 5: Hydration.** Client Components like `SaveButton` and `ShareButton` hydrate — their JavaScript loads and attaches event handlers.

## Reading the Prisma schema

The schema tells you the domain model before you read a single line of application code:

```prisma
model Company {
  id       String   @id @default(cuid())
  name     String   @unique
  layoffs  Layoff[]
}

model Layoff {
  id         String   @id @default(cuid())
  company    Company  @relation(fields: [companyId], references: [id])
  companyId  String
  headcount  Int
  reportedAt DateTime
  article    Article? @relation(fields: [articleId], references: [id])
  articleId  String?
}

model Article {
  id          String   @id @default(cuid())
  slug        String   @unique
  title       String
  body        String
  isPremium   Boolean  @default(false)
  publishedAt DateTime @default(now())
  layoffs     Layoff[]
  tags        Tag[]
}
```

From this schema alone you can infer: a company can have multiple layoffs, each layoff can be linked to an article, articles can be premium, and articles have tags for categorization.

## The singleton pattern for Prisma

In `lib/prisma.ts`, the project creates one Prisma client instance and reuses it:

```tsx
import { PrismaClient } from "@prisma/client";

const globalForPrisma = globalThis as unknown as { prisma: PrismaClient };

export const prisma = globalForPrisma.prisma || new PrismaClient();

if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;
```

This prevents creating a new database connection on every hot reload in development. In production, there's only one process, so it's simpler — but the pattern is needed for dev.

<Code>
```tsx
// Trace exercise: identify which components are Server vs Client
// app/articles/[slug]/page.tsx — SERVER (no "use client", fetches from DB)
import { prisma } from "@/lib/prisma";
import { SaveButton } from "@/components/SaveButton";
import { TagList } from "@/components/TagList";

export default async function ArticlePage({ params }: { params: { slug: string } }) {
  const article = await prisma.article.findUnique({
    where: { slug: params.slug },
    include: { tags: true },
  });

  if (!article) return notFound();

  return (
    <article className="max-w-3xl mx-auto p-6">
      <h1 className="text-3xl font-bold">{article.title}</h1>
      <TagList tags={article.tags} />       {/* Server Component — just renders props */}
      <div className="prose">{article.body}</div>
      <SaveButton articleId={article.id} /> {/* Client Component — needs onClick */}
    </article>
  );
}
```
</Code>

<CommonMistakes>
- **Skipping the schema** — always read `schema.prisma` before the application code; it's the fastest way to understand the domain
- **Assuming every component with JSX is a Client Component** — in App Router, Server Components also return JSX
- **Ignoring the `lib/` folder** — shared utilities like the Prisma singleton and auth config are critical infrastructure
- **Not tracing the full request path** — understanding routing → data fetch → render → hydration is essential for debugging
</CommonMistakes>
