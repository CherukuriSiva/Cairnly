## What you're building

A content site on a topic you care about. It could be:
- A tech news aggregator (like the layoffs tracker)
- A recipe site with free and premium tiers
- A study guide site for a college course
- A local events directory

The specific topic doesn't matter. What matters is that you use every layer of the stack.

## Requirements

Your site must include:

### Data layer
- [ ] Prisma schema with at least 4 models and 2 relationships
- [ ] CUIDs for IDs, slugs for URLs, timestamps on mutable models
- [ ] At least one enum (e.g., access tier, category)
- [ ] Seed script to populate initial data

### Pages and routing
- [ ] Home page with a listing of content items
- [ ] Dynamic detail page (`/[slug]`) for individual items
- [ ] At least one filtered/sorted listing (by category, date, or tag)
- [ ] 404 page using `notFound()`

### SEO
- [ ] `generateMetadata` on every dynamic page
- [ ] Open Graph tags for social previews
- [ ] `sitemap.ts` generating URLs from the database

### Auth
- [ ] NextAuth with at least one OAuth provider
- [ ] Protected page that requires sign-in
- [ ] User-specific data (saved items, preferences)

### Payments
- [ ] Stripe Checkout for premium access
- [ ] Webhook handler that updates the database
- [ ] Content gating based on payment status

### UI
- [ ] Reusable components: card, badge, page shell
- [ ] `cn()` utility with `clsx` + `tailwind-merge`
- [ ] Responsive layout (works on mobile and desktop)
- [ ] Loading skeletons for async content

### Deployment
- [ ] Deployed to Vercel with a live URL
- [ ] Environment variables configured properly
- [ ] Production database with migrations applied
- [ ] README with setup instructions

## Recommended order of operations

1. **Schema first** — design your Prisma models based on your content domain
2. **Seed data** — write a seed script so you have content to display
3. **Pages and components** — build the listing and detail pages
4. **SEO** — add `generateMetadata` and `sitemap.ts`
5. **Auth** — integrate NextAuth and protect a page
6. **Payments** — add Stripe Checkout and content gating
7. **Polish** — responsive design, loading states, error pages
8. **Deploy** — push to Vercel, configure env vars, test live
9. **README** — document what you built and how to run it

## The seed script

Every content site needs sample data. Create a seed script:

```tsx
// prisma/seed.ts
import { PrismaClient } from "@prisma/client";

const prisma = new PrismaClient();

async function main() {
  await prisma.category.createMany({
    data: [
      { name: "Analysis", slug: "analysis" },
      { name: "Breaking News", slug: "breaking-news" },
      { name: "Opinion", slug: "opinion" },
    ],
  });

  await prisma.article.create({
    data: {
      title: "Tech Layoffs Hit Record Highs in Q1 2026",
      slug: "tech-layoffs-q1-2026",
      body: "An in-depth analysis of the layoff trends...",
      excerpt: "Q1 2026 saw the highest tech layoffs since the pandemic era.",
      accessTier: "FREE",
      categoryId: (await prisma.category.findFirst({ where: { slug: "analysis" } }))!.id,
      authorId: "seed-author-id",
    },
  });

  console.log("Seeded database");
}

main().catch(console.error).finally(() => prisma.$disconnect());
```

Add to `package.json`:

```json
{
  "prisma": {
    "seed": "tsx prisma/seed.ts"
  }
}
```

Run with `npx prisma db seed`.

```tsx
// Seed script pattern
// prisma/seed.ts
import { PrismaClient } from "@prisma/client";
const prisma = new PrismaClient();

async function main() {
  // Clear existing data (idempotent seeding)
  await prisma.article.deleteMany();
  await prisma.category.deleteMany();

  const categories = await Promise.all([
    prisma.category.create({ data: { name: "Analysis", slug: "analysis" } }),
    prisma.category.create({ data: { name: "News", slug: "news" } }),
  ]);

  await prisma.article.createMany({
    data: Array.from({ length: 10 }, (_, i) => ({
      title: `Sample Article ${i + 1}`,
      slug: `sample-article-${i + 1}`,
      body: `Content for article ${i + 1}...`,
      categoryId: categories[i % 2].id,
      accessTier: i < 7 ? "FREE" : "PREMIUM",
    })),
  });

  console.log("Database seeded successfully");
}

main().finally(() => prisma.$disconnect());
```

<TryItYourself>

2. Design your Prisma schema — draw the ERD on paper first
3. Build the data layer: schema, migration, seed script
4. Build pages one at a time: listing, then detail, then filtered view
5. Add SEO, auth, and payments in that order
6. Deploy to Vercel after each major milestone (not just at the end)
7. Write a README that explains the architecture
8. Share the live URL with a friend or mentor for review
</TryItYourself>

<CommonMistakes>
- **Building the UI before the schema** — the schema is the foundation; everything else depends on it
- **Deploying only at the end** — deploy early and often; catching env var issues on day 1 is better than day 7
- **Skipping the seed script** — without sample data, your site looks empty and broken
- **Not writing a README** — recruiters and interviewers check the repo first; a missing README suggests the project is a throwaway
- **Overscoping** — a polished site with 4 models beats a broken site with 12; ship something complete
</CommonMistakes>
