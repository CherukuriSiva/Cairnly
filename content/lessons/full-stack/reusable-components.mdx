## The component toolkit for content sites

Every content site needs these five components. We'll build each one:

1. **ArticleCard** — a clickable card showing title, excerpt, date, and tags
2. **Badge** — a small colored label for tags, categories, and status
3. **PageShell** — a layout wrapper with consistent max-width, padding, and heading
4. **CallToAction** — a section prompting the user to subscribe or sign up
5. **Skeleton** — loading placeholders that match component dimensions

## Pattern: `className` merging with `cn()`

The most important utility in any Tailwind project is a `cn()` function that merges class names intelligently:

```tsx
// lib/cn.ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

`clsx` handles conditional classes. `twMerge` resolves Tailwind conflicts (e.g., `p-4` and `p-6` — the last one wins). Every component should accept an optional `className` prop and merge it:

```tsx
function Badge({ children, className }: { children: React.ReactNode; className?: string }) {
  return (
    <span className={cn("rounded-full px-2 py-0.5 text-xs font-medium bg-gray-100 text-gray-700", className)}>
      {children}
    </span>
  );
}

// Usage: override the default colors
<Badge className="bg-red-100 text-red-700">Layoff</Badge>
```

## Building the ArticleCard

A good ArticleCard is a Server Component (no interactivity needed) with a clean prop interface:

```tsx
// components/ArticleCard.tsx
import Link from "next/link";
import { Badge } from "./Badge";
import { cn } from "@/lib/cn";

interface ArticleCardProps {
  slug: string;
  title: string;
  excerpt: string;
  publishedAt: Date;
  tags: { name: string }[];
  className?: string;
}

export function ArticleCard({ slug, title, excerpt, publishedAt, tags, className }: ArticleCardProps) {
  return (
    <Link
      href={`/articles/${slug}`}
      className={cn(
        "block rounded-lg border border-gray-200 p-5 hover:border-gray-400 transition-colors",
        className
      )}
    >
      <h3 className="text-lg font-semibold text-gray-900">{title}</h3>
      <p className="mt-1 text-sm text-gray-600 line-clamp-2">{excerpt}</p>
      <div className="mt-3 flex items-center gap-2">
        <time className="text-xs text-gray-500">
          {publishedAt.toLocaleDateString("en-US", { month: "short", day: "numeric", year: "numeric" })}
        </time>
        {tags.map((tag) => (
          <Badge key={tag.name}>{tag.name}</Badge>
        ))}
      </div>
    </Link>
  );
}
```

## Building the PageShell

Instead of repeating `max-w-4xl mx-auto px-4` on every page, wrap it:

```tsx
// components/PageShell.tsx
import { cn } from "@/lib/cn";

interface PageShellProps {
  title: string;
  subtitle?: string;
  children: React.ReactNode;
  className?: string;
}

export function PageShell({ title, subtitle, children, className }: PageShellProps) {
  return (
    <main className={cn("mx-auto max-w-4xl px-4 py-10", className)}>
      <header className="mb-8">
        <h1 className="text-3xl font-bold tracking-tight text-gray-900">{title}</h1>
        {subtitle && <p className="mt-2 text-lg text-gray-600">{subtitle}</p>}
      </header>
      {children}
    </main>
  );
}
```

Now every page is just:

```tsx
export default function ArticlesPage() {
  return (
    <PageShell title="Articles" subtitle="Latest layoff analysis and reports">
      {/* content */}
    </PageShell>
  );
}
```

## Component API design principles

1. **Accept `className` on every component** — consumers will always need to adjust spacing or colors
2. **Use TypeScript interfaces, not inline types** — makes the API self-documenting
3. **Prefer composition over configuration** — instead of a `variant` prop with 10 options, let consumers compose with `className`
4. **Keep components as Server Components unless they need interactivity** — less client JS, faster pages
5. **Use semantic HTML** — `<article>`, `<time>`, `<nav>` — better for accessibility and SEO

<CommonMistakes>
- **Not using `tailwind-merge`** — without it, `cn("p-4", "p-6")` outputs `"p-4 p-6"` (both classes applied, last one wins by CSS specificity, which is unpredictable)
- **Making every component a Client Component** — a card that displays data and a link doesn't need `"use client"`
- **Hardcoding colors instead of accepting `className`** — kills reusability; the consumer knows their context better than the component
- **Skipping the loading skeleton** — content sites have data-fetching latency; without skeletons, the page feels broken during loading
</CommonMistakes>
