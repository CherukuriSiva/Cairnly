## What makes a solution file stand out

Don't just dump code. Add context:

```python
"""
LeetCode 15: 3Sum
Pattern: Two Pointers (converging on sorted array)
Difficulty: Medium
Time: O(n^2)  |  Space: O(1) excluding output

Key insight: Fix one element, then use two-pointer on the remainder.
Skip duplicates at all three levels to avoid duplicate triplets.

Related: Two Sum, 4Sum, 3Sum Closest
"""

def three_sum(nums):
    nums.sort()
    result = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        left, right = i + 1, len(nums) - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total == 0:
                result.append([nums[i], nums[left], nums[right]])
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1
            elif total < 0:
                left += 1
            else:
                right -= 1
    return result
```

The header takes 30 seconds to write and immediately shows: pattern knowledge, complexity awareness, and the ability to connect related problems.

## Resume framing

**Don't write:**
- "Solved 300+ LeetCode problems"
- "Strong in data structures and algorithms"

**Do write:**
- "Built a categorized DSA solutions portfolio covering 12 algorithmic patterns with complexity analysis (github.com/you/dsa-solutions)"
- "Demonstrated systematic problem-solving: pattern recognition, brute-force to optimal progression, and edge-case analysis"

On your resume, DSA mastery is best shown indirectly:
- **Projects section**: Link your solutions repo if it's well-organized
- **Skills section**: List specific patterns (not "algorithms" generically)
- **Experience section**: Mention algorithmic thinking in context ("Optimized search from O(n^2) to O(n log n) using binary search on sorted intervals")

## In behavioral interviews

When asked "tell me about a challenging technical problem," your DSA practice is fair game if you frame it well:

**Weak answer:** "I solved a hard LeetCode problem."

**Strong answer:** "I was working on a real-time notification system and realized the core problem was identical to the meeting rooms interval scheduling problem. By applying a sweep-line algorithm, I reduced the peak memory usage by 60% compared to the naive approach that tracked every active notification individually."

Connect the pattern to a real or realistic scenario. This shows you can transfer interview knowledge to production work.

## The progress tracker

In your repo's main README, maintain a table:

```markdown
| Pattern | Problems Solved | Confidence |
|---|---|---|
| Two Pointers | 8 | High |
| Sliding Window | 6 | High |
| Binary Search | 5 | Medium |
| DP | 4 | Low - need more practice |
| Graphs | 3 | Medium |
```

This is for you, not the recruiter. It keeps your prep focused on weak areas.
