<WhyThisMatters>
When a regulator, customer, or incident-response team asks "why did the AI return *that* answer to *that* user on *that* day?", application logs full of `print()` statements won't save you. A proper audit trail — who asked what, which documents were retrieved, what was returned, and whether guardrails fired — is a compliance requirement in finance, healthcare, and enterprise SaaS.
</WhyThisMatters>

<Body>
## Audit log ≠ debug log

Debug logs help *you* fix bugs and get rotated away. Audit logs prove *what happened* to someone else, months later. They must be **append-only**, **immutable**, and **complete enough to reconstruct a decision**.

## What to capture per request

A useful event schema for an AI interaction:

- `event_id`, `timestamp` (UTC), `user_id`, `tenant_id`
- `action` (e.g. `rag_query`), query *fingerprint* (hash, not raw text if it may contain PII)
- `retrieved_doc_ids` and their access decision
- `guardrails`: which fired (injection blocked? PII redacted? refused?)
- `model`, `tokens`, `latency_ms`, `cost`
- `outcome` (answered / refused / error)

Capturing retrieved doc IDs and guardrail outcomes is what lets you answer "why this answer?".

## Tamper-evidence

Append-only is the baseline. For stronger guarantees, chain each event's hash to the previous one (a hash chain), so any deletion or edit breaks the chain and is detectable.

## Don't store PII in the audit log

Ironically, the audit log itself can become a breach. Log a **hash or fingerprint** of sensitive fields, not the raw value — enough to correlate, not enough to leak.

## Ship to a SIEM

Emit one structured JSON event per interaction and forward it to your SIEM (Datadog, Splunk, CloudTrail). Structured events are queryable; free-text logs are not.
</Body>

<Code>
```python
import json, hashlib, time

def audit_event(*, user, action, query, retrieved_ids, guardrails, outcome, usage) -> dict:
    return {
        "event_id": new_uuid(),
        "ts": iso_utc(time.time()),
        "user_id": user.id,
        "tenant_id": user.tenant_id,
        "action": action,
        "query_fingerprint": hashlib.sha256(query.encode()).hexdigest()[:16],  # not raw PII
        "retrieved_doc_ids": retrieved_ids,
        "guardrails": guardrails,          # e.g. {"injection": False, "pii_redacted": True, "refused": False}
        "model": usage["model"],
        "tokens": usage["tokens"],
        "latency_ms": usage["latency_ms"],
        "outcome": outcome,                # "answered" | "refused" | "error"
    }

def emit(event: dict, prev_hash: str) -> str:
    """Append-only + hash chain for tamper-evidence; forward to SIEM."""
    event["prev_hash"] = prev_hash
    event["hash"] = hashlib.sha256((prev_hash + json.dumps(event, sort_keys=True)).encode()).hexdigest()
    siem_sink.write(json.dumps(event))     # Datadog / Splunk / CloudTrail
    return event["hash"]
```

<CommonMistakes>
- **Treating debug logs as audit logs** — they get rotated and aren't tamper-evident
- **Storing raw PII in the audit trail** — the log becomes the breach; hash sensitive fields
- **Not logging retrieved doc IDs** — you can't reconstruct *why* an answer was given
- **Free-text logs** — unqueryable; emit structured JSON
- **No tamper-evidence** — without a hash chain, deletions are invisible
- **Logging only failures** — you need the full trail, including successful answers
</CommonMistakes>
