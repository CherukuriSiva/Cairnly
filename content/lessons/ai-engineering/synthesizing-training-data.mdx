<WhyThisMatters>
Most real datasets are missing the exact behaviors you most need: refusing out-of-scope questions, handling follow-ups, staying grounded. You can't always collect those from users, but you can synthesize them. Teams that know how to generate clean refusal and multi-turn data ship safer assistants without waiting months for labeled examples.
</WhyThisMatters>

<Body>
## Why synthesize at all

A factuality dataset teaches the model to answer. It does **not** teach the model to *refuse* — because nobody writes down the questions a system should decline. Synthetic data fills these gaps: refusals, multi-turn follow-ups, and edge cases that are rare in the wild.

## Refusal synthesis

You want examples where the correct output is a polite, consistent refusal. Take off-topic or unsafe seed questions and pair them with a fixed refusal message. The model learns the *shape* of "this is out of scope" rather than hallucinating an answer.

## Multi-turn synthesis

Real conversations have follow-ups ("what about for adults?"). Generate these by taking a single-turn QA pair and asking a strong model to extend it into a 2–3 turn exchange, preserving grounding in the same context.

## Schema discipline

Synthetic ≠ sloppy. Every generated record must validate against the same schema as your real data — same fields (`instruction`, `input`, `output`), same types. A record that doesn't validate gets dropped, not trained on.
</Body>

<Code>
```python
from dataclasses import dataclass

REFUSAL_MESSAGE = "I can only answer questions about the provided documents."

@dataclass
class Record:
    instruction: str
    input: str   # retrieved context (empty for refusals)
    output: str

def synthesize_refusals(off_topic_questions: list[str]) -> list[Record]:
    """Pair out-of-scope questions with a consistent refusal output."""
    return [
        Record(instruction=q, input="", output=REFUSAL_MESSAGE)
        for q in off_topic_questions
    ]

def synthesize_multiturn(seed: Record, generate) -> list[dict]:
    """Extend a single-turn QA pair into a short grounded conversation."""
    prompt = (
        "Extend this Q&A into a 2-turn conversation. The follow-up must be "
        "answerable from the SAME context. Return JSON list of {role, content}.\n\n"
        f"Q: {seed.instruction}\nContext: {seed.input}\nA: {seed.output}"
    )
    return parse_json(generate(prompt))  # validate before keeping
```

<CommonMistakes>
- **Using one refusal phrasing for everything** — the model overfits to the exact string; vary the surface form a little
- **Not validating synthetic records** — a malformed JSON record poisons training silently
- **Over-synthesizing** — too much synthetic data drowns out real signal; treat it as seasoning, not the meal
- **Generating multi-turn that breaks grounding** — the follow-up must stay answerable from the original context
- **Skipping dedup** — a strong model emits near-duplicate questions; they bias the dataset
</CommonMistakes>
