<WhyThisMatters>
An agent without memory repeats itself: it calls the same tool, forgets what it already learned, and never converges. But naive "remember everything" blows the context window and the cost with it. Knowing how to keep the *right* history within budget is the difference between an agent that solves a task in 3 steps and one that loops uselessly.
</WhyThisMatters>

<Body>
## Two kinds of memory

- **Short-term memory** — the current session's message history: the task, each Thought/Action, and every Observation. This is what lets the agent reason across steps.
- **Long-term memory** — facts persisted across sessions, usually in a vector store and retrieved on demand (that's just RAG wearing a different hat).

This lesson is about short-term memory, the engine of multi-step reasoning.

## The simplest memory: a message list

At its core, memory is an append-only list of `{role, content}` messages. Add the user task, add each assistant response, add each observation. The agent loop reads this list every iteration. Clear it when a new task starts.

```python
class AgentMemory:
    def __init__(self):
        self.history: list[dict[str, str]] = []
    def add_message(self, role: str, content: str):
        self.history.append({"role": role, "content": content})
    def get_messages(self) -> list[dict[str, str]]:
        return self.history
    def clear(self):
        self.history = []
```

## Keeping it in budget

History grows every step and the context window is finite. Two standard strategies:

1. **Rolling window** — keep the last N turns (plus the original task, which you should *never* drop).
2. **Summarization** — when history gets long, compress older turns into a short summary and keep recent turns verbatim.

The original task and recent observations are the highest-value tokens; protect them.
</Body>

<BookNote chapter="6">

The book describes memory in three layers. Internal knowledge is what the model learned during
training and cannot be changed without retraining. Short-term memory is the context window:
whatever you put in the current prompt, which disappears after the call. Long-term memory is
external storage the agent can read from and write to, such as a database or a vector index.

Why bother? Without memory, an agent forgets everything between sessions and runs out of room in
long tasks. With it, the agent can keep track of user preferences, earlier decisions and
intermediate results, and stay consistent over many steps.

Managing memory is a design problem with trade-offs. The context window fills up, so you must
decide what to keep, summarise or drop, for example keeping recent turns verbatim and older ones
as short summaries. Long-term stores can collect outdated or conflicting facts, so new
information needs a rule for whether it adds to or replaces what is stored. Retrieval from
memory is just another retrieval problem, and it deserves the same testing.

Further reading: Chip Huyen, AI Engineering (O'Reilly, 2025), chapter 6

</BookNote>

<Code>
```python
class WindowedMemory:
    """Keeps the task + the last `window` messages to stay within budget."""
    def __init__(self, window: int = 12):
        self.window = window
        self.task: dict | None = None
        self.history: list[dict] = []

    def add_message(self, role: str, content: str):
        msg = {"role": role, "content": content}
        if self.task is None and role == "user":
            self.task = msg          # pin the original task forever
        self.history.append(msg)

    def get_messages(self) -> list[dict]:
        recent = self.history[-self.window:]
        # always include the pinned task even if it scrolled out of the window
        if self.task and self.task not in recent:
            return [self.task, *recent]
        return recent

    def clear(self):
        self.task, self.history = None, []
```

<CommonMistakes>
- **Dropping the original task** when windowing — the agent forgets what it's doing
- **Never trimming** — history outgrows the context window and requests start failing
- **Storing raw tool dumps** — huge observations eat the budget; trim or summarize them
- **Confusing short-term and long-term memory** — cross-session facts belong in a vector store, not the message list
- **Not clearing memory between tasks** — stale history bleeds into the next run
</CommonMistakes>
