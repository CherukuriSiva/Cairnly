The difference between "I used LangChain" and a clear architecture walkthrough is often the difference between a pass and a fail.

<Body>
## The 60-second structure

Lead with the loop, then the components, then the rails:

1. **The loop** — "It's a ReAct loop: the model produces a Thought, requests an Action, my controller runs it and feeds back an Observation, and it repeats until it emits a final Answer."
2. **The components** — controller, LLM client, tool registry, memory, reflection.
3. **The rails** — max-iterations cap, tool registry as a safety barrier, reflection to catch ungrounded answers.

## The five components to name

- **Controller** — orchestrates the loop, parses output, decides action vs answer.
- **Tool registry** — the vetted set of actions; the safety barrier between model and business logic.
- **Memory** — the running history of thoughts/actions/observations within the context budget.
- **LLM client** — the model call, with timeout/retry and cost tracking.
- **Reflection** — a post-hoc judge that validates the answer against gathered observations.

## Pre-empt the obvious follow-ups

- *"Why an agent and not a single prompt?"* — "When the task needs tools or multiple dependent steps the model can't do in one shot. If a prompt suffices, I use a prompt."
- *"How do you stop it looping forever / burning money?"* — "Hard max-iterations cap plus per-run cost tracking."
- *"How do you keep it from hallucinating?"* — "Reflection against the observations it actually collected."
</Body>

<Code>
```text
60-SECOND SCRIPT (rehearse out loud):

"I built a research agent on a ReAct loop. The model emits a Thought and an
Action — a named tool plus input — and pauses. My controller, not the model,
executes the tool through a registry and feeds the result back as an
Observation. It loops until it outputs a final Answer.

Five pieces: a controller that parses output and drives the loop; a tool
registry that's both the discovery layer and the safety barrier; short-term
memory holding the thought/action/observation history; an LLM client with
timeouts, retries, and cost tracking; and a reflection step that checks the
final answer against the observations it gathered.

Two rails keep it safe: a hard max-iterations cap so it can't loop forever,
and reflection to catch any claim the observations don't support. I'd only
use an agent when the task genuinely needs tools or multi-step reasoning —
otherwise a single prompt is cheaper and more reliable."
```
</Code>

<CommonMistakes>
- **Leading with a framework name** ("I used LangChain") instead of the architecture
- **Describing only the happy path** — interviewers probe failure modes
- **Forgetting the safety rails** — no max-iterations / no reflection reads as junior
- **Rambling** — structure beats detail; loop → components → rails
- **Claiming "agent" for what's really a single prompt** — know the distinction
</CommonMistakes>
