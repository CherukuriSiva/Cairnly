<WhyThisMatters>
The classic enterprise RAG disaster: an employee asks "what's the CEO's salary?" and the assistant cheerfully retrieves it from an HR doc and answers — because retrieval ignored permissions. In a multi-tenant or role-based system, access control has to live at the *chunk* level and be enforced *before* the LLM ever sees the content. This is the most common enterprise-RAG design question.
</WhyThisMatters>

<Body>
## Why RAG breaks access control

Traditional apps check "can this user open this document?" at the document boundary. RAG shreds documents into chunks and retrieves them by similarity — there is no document-open event to gate. If you don't carry permissions down to the chunk, retrieval will happily surface a chunk from a file the user can't access.

## Tag every chunk with access metadata

When you ingest and chunk a document, copy its access control onto each chunk:

```python
chunk = {
    "text": "...",
    "embedding": [...],
    "tenant_id": "acme",
    "allowed_roles": ["hr", "exec"],   # who may retrieve this chunk
    "source_doc": "comp-2026.pdf",
}
```

## Enforce in the query (pre-filter), not after

The only safe place to enforce access is **inside the retrieval query** as a metadata filter, so forbidden chunks are never returned:

```python
results = index.query(
    vector=embed(query),
    top_k=5,
    filter={"tenant_id": user.tenant_id,
            "allowed_roles": {"$in": user.roles}},
)
```

Filtering *after* retrieval is unsafe: the forbidden text already entered your process, and one bug leaks it. Pre-filtering means the model literally never sees it.

## The summarization leak

Even with citations hidden, an LLM that *received* a forbidden chunk can leak its content in a summary. That's why enforcement must happen before generation — never "retrieve everything, then redact."
</Body>

<Code>
```python
def secure_retrieve(index, query: str, user) -> list[dict]:
    """Retrieve only chunks this user's tenant + roles are allowed to see."""
    acl_filter = {
        "tenant_id": user.tenant_id,                 # tenant isolation
        "allowed_roles": {"$in": user.roles},        # role-based access
    }
    return index.query(vector=embed(query), top_k=5, filter=acl_filter)

def answer_with_rbac(index, query: str, user, llm) -> str:
    chunks = secure_retrieve(index, query, user)
    if not chunks:
        return "I couldn't find anything you have access to on that."
    context = "\n".join(c["text"] for c in chunks)
    return llm(build_prompt(query, context))         # model only ever sees allowed text
```
</Code>

<CommonMistakes>
- **Document-level checks only** — chunks lose their parent's permissions
- **Filtering after retrieval** — the forbidden text already entered your process
- **Forgetting tenant isolation** — role checks alone don't separate customers
- **Trusting the LLM to "not mention" forbidden content** — it leaks via summaries
- **Not re-applying ACLs on re-index** — permission changes must propagate to chunks
</CommonMistakes>
