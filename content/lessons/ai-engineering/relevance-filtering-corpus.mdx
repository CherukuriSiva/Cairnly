<Body>
## Off-topic in, off-topic out

If your customer-support assistant ingests generic web text, retrieval will sometimes pull those generic passages for a domain question, and the LLM will dutifully ground its answer in them. Garbage in the index becomes garbage in the answer. Filtering relevance at ingestion is cheaper and safer than trying to fix it at query time.

## Stage 1: a keyword filter

Start simple. A curated keyword set plus a check over the document's title, a context snippet, and the question catches the obvious off-topic material for free:

```python
SUPPORT_KEYWORDS = frozenset({"order", "refund", "invoice", "billing",
                              "shipping", "account", "password", "subscription", ...})

def is_on_topic(record: dict) -> bool:
    text = f"{record.get('source_article','')} {record.get('input','')[:200]} {record.get('instruction','')}".lower()
    return any(kw in text for kw in SUPPORT_KEYWORDS)
```

## Stage 2: embedding-based relevance

Keywords miss paraphrases and synonyms. The upgrade: embed each candidate and keep it only if its similarity to a set of *topic anchor* embeddings clears a threshold. Same idea, semantic instead of lexical.

## Monitor the pass rate

The dangerous failure is a filter that silently passes everything (a bug, an empty keyword set). Track the pass rate and **alert when it leaves the expected band** — e.g. warn if it drops below 90% on pre-curated sources, since that signals either bad data or a broken filter.
</Body>

<Code>
```python
import logging
logger = logging.getLogger(__name__)

def filter_on_topic(records: list[dict]) -> tuple[list[dict], list[dict]]:
    on_topic, rejected = [], []
    for r in records:
        (on_topic if is_on_topic(r) else rejected).append(r)

    total = len(records)
    pass_rate = len(on_topic) / total if total else 1.0
    if pass_rate < 0.90:                       # broken filter / bad source
        logger.warning("On-topic pass rate %.1f%% (%d/%d) — below 90%% threshold",
                       pass_rate * 100, len(on_topic), total)
    else:
        logger.info("On-topic: %d/%d passed (%.1f%%), %d rejected",
                    len(on_topic), total, pass_rate * 100, len(rejected))
    return on_topic, rejected
```
</Code>

<CommonMistakes>
- **No relevance filter** — off-topic docs surface in retrieval and mislead the LLM
- **Keyword set too narrow** — rejects valid on-topic docs (low pass rate for the wrong reason)
- **No pass-rate monitoring** — a broken filter passes everything silently
- **Filtering at query time only** — cheaper and cleaner to filter at ingestion
- **Keyword-only forever** — upgrade to embeddings to catch paraphrases
</CommonMistakes>
