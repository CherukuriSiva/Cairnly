<Body>
## What FAISS gives you — and what it doesn't

FAISS is a blazing-fast similarity search library. It does one thing: given a query vector, find the nearest stored vectors. It does **not** give you persistence, multi-tenancy, access control, or filtering by attributes out of the box.

## Metadata filtering is the real feature

In production you rarely want "the nearest vectors" — you want "the nearest vectors **that this user is allowed to see**, from **this project**, written **after this date**." That's a metadata filter applied alongside the similarity search:

```python
results = index.query(
    vector=embed(query),
    top_k=5,
    filter={
        "tenant_id": user.tenant_id,
        "allowed_roles": {"$in": user.roles},
        "created_at": {"$gte": "2026-01-01"},
    },
)
```

This single capability is why teams move off raw FAISS.

## Picking a vector store

- **pgvector** — you already run Postgres; you want vectors next to your relational data with one fewer system to operate.
- **Pinecone** — fully managed, you don't want to run infrastructure, metadata filtering built in.
- **Milvus / Qdrant / Weaviate** — open-source, self-hosted, high scale and tunable indexes.

The right answer is "the one your team can operate." Don't adopt a distributed vector DB to serve 10K documents.
