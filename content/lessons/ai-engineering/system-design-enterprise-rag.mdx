<Body>
## Drive the flow, don't list boxes

Walk it as a request's journey and name a trade-off at each stage.

**1. Ingestion.** Source connectors → parse/OCR → PII sanitization → recursive chunking with metadata (tenant, allowed_roles, source, timestamp). *Trade-off:* chunk size vs context completeness.

**2. Index.** Embed chunks into a vector DB that supports metadata filtering and multi-tenant namespaces. *Trade-off:* managed (Pinecone) vs self-hosted (Milvus) — operability vs control.

**3. Retrieval with RBAC.** Embed the query, retrieve top-k **filtered by the user's tenant + roles** so forbidden chunks never return. Enforcement is pre-filter, never post-redaction.

**4. Guardrails (input).** Sanitize, detect prompt injection (direct *and* indirect via retrieved content), redact PII.

**5. Generation.** Build a grounded prompt with numbered citations; the model answers only from context.

**6. Guardrails (output).** Verify groundedness / citations; refuse or disclaim on failure.

**7. Observability + ops.** Audit log per request (who/what/retrieved-ids/guardrails/outcome), drift monitoring on query embeddings, semantic cache for latency, and provider fallback/circuit breakers for HA.

## The enterprise checklist interviewers want

Multi-tenancy, chunk-level RBAC, compliance audit trail, monitoring/drift, high availability, and cost controls. Mention these unprompted — that's the senior signal.
</Body>

<CommonMistakes>
- **Listing boxes with no trade-offs** — naming components isn't design
- **Forgetting RBAC and multi-tenancy** — the #1 enterprise gap
- **Post-redaction instead of pre-filtering** — leaks forbidden content
- **Ignoring observability** — no audit/drift/monitoring reads as a prototype, not a system
- **No failover story** — enterprises ask about HA and provider outages
- **Skipping cost** — caching and model tiering should appear
</CommonMistakes>
