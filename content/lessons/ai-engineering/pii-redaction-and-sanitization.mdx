<WhyThisMatters>
PII flows through AI apps constantly — users paste their email to reset a password, a retrieved document contains a customer's phone number. If that PII lands in a log, a prompt sent to a third-party API, or a generated response, you have a compliance incident. Redaction and output sanitization are the cheapest controls that keep you out of that headline.
</WhyThisMatters>

<Body>
## Redact, don't block

A user typing "my email is jane@acme.com, reset my password" is making a *legitimate* request. Blocking it is bad UX. The right move is to **redact** the PII and let the request continue, so the model never sees the raw value and your logs stay clean.

## Detect the common patterns

Regex handles the well-structured identifiers cheaply and instantly:

```python
import re

PII_PATTERNS = {
    "ssn": r"\b\d{3}-\d{2}-\d{4}\b",
    "email": r"\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b",
    "phone": r"\b\(?\d{3}\)?[\s.-]?\d{3}[\s.-]?\d{4}\b",
    "credit_card": r"\b\d{4}[\s-]?\d{4}[\s-]?\d{4}[\s-]?\d{4}\b",
}

def redact_pii(text: str) -> str:
    for kind, pattern in PII_PATTERNS.items():
        text = re.sub(pattern, f"[REDACTED_{kind.upper()}]", text)
    return text
```

## Sanitize at two boundaries

- **Input boundary** — sanitize and redact *before* the prompt is built, so PII never reaches a third-party model or your logs.
- **Output boundary** — the model can echo PII back from its context or training data; scan the generated answer too before returning it.

## When regex isn't enough

Regex misses names, addresses, and context-dependent identifiers. For regulated workloads, graduate to a dedicated engine (Microsoft Presidio, AWS Macie) that does NER-based detection. Start with regex; escalate when the compliance bar demands it.
</Body>

<Code>
```python
def sanitize_input(text: str) -> str:
    text = text.replace("\x00", "")
    text = re.sub(r"\s+", " ", text).strip()
    return redact_pii(text)            # redact before the model ever sees it

def sanitize_output(answer: str) -> tuple[str, bool]:
    """Scan generated text for leaked PII before returning to the user."""
    leaked = any(re.search(p, answer) for p in PII_PATTERNS.values())
    return redact_pii(answer), leaked  # redact + flag for logging/alerting

# Demo
print(sanitize_input("My SSN is 123-45-6789, what benefits apply?"))
clean, leaked = sanitize_output("Per the file, contact jane@acme.com.")
print(clean, "| leaked:", leaked)
```

<CommonMistakes>
- **Blocking instead of redacting** — kills legitimate requests
- **Only sanitizing input** — the model can leak PII into the output from context
- **Logging raw requests before redaction** — the log itself becomes the breach
- **Over-trusting regex** — it misses names/addresses; escalate for regulated data
- **Redacting inconsistently** — use stable placeholders so downstream code can detect them
</CommonMistakes>
