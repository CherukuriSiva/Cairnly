<Body>
## The layered layout

A maintainable AI backend separates concerns into directories:

- **`api/router.py`** — the top-level router that mounts each feature router under a prefix.
- **`api/endpoints/`** — one module per concern: `chat.py`, `documents.py`, `health.py`.
- **`core/`** — cross-cutting infrastructure: `config.py` (typed settings), `logger.py`, `errors.py`.
- **`ai/`** — the domain logic: `rag/`, `agent/`, `governance/`, `mlops/`.

Routes are thin; the real work lives in `ai/` and is called from the endpoints.

## Mount routers under prefixes

The top-level router composes feature routers, each with a prefix and tags. Adding a feature is adding a module and one `include_router` line — no edits to existing endpoints:

```python
from fastapi import APIRouter
from app.api.endpoints import health, documents, chat

api_router = APIRouter()
api_router.include_router(health.router,    prefix="/health",    tags=["health"])
api_router.include_router(documents.router, prefix="/documents", tags=["documents"])
api_router.include_router(chat.router,      prefix="/chat",      tags=["chat"])
```

## Centralize configuration

A single typed `Settings` object (Pydantic `BaseSettings`) reads environment variables once and is imported everywhere. No scattered `os.getenv` calls, and missing/mistyped config fails loudly at startup.

## `main.py` composes the app

`main.py` stays small: create the app with a lifespan (load models once), attach middleware (logging, CORS), and include the router. It's the wiring, not the logic.
</Body>

<Code>
```python
# app/core/config.py
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    OPENAI_API_KEY: str | None = None
    VECTOR_DB_URL: str = "http://localhost:6333"
    MAX_BUDGET_USD: float = 50.0
    class Config:
        env_file = ".env"

settings = Settings()   # read once, import everywhere

# main.py
from contextlib import asynccontextmanager
from fastapi import FastAPI
from app.api.router import api_router
from app.core.logger import logging_middleware

@asynccontextmanager
async def lifespan(app: FastAPI):
    load_models()          # once, before traffic
    yield

app = FastAPI(title="AI Service", lifespan=lifespan)
app.middleware("http")(logging_middleware)
app.include_router(api_router, prefix="/api/v1")   # everything mounts here
```

<CommonMistakes>
- **Everything in one `main.py`** — unmaintainable as features grow
- **Scattered `os.getenv`** — centralize in a typed settings object
- **Fat route handlers** — keep routes thin; put logic in `ai/`
- **Loading models per request** — do it once in lifespan
- **No API versioning prefix** — `/api/v1` lets you evolve without breaking clients
</CommonMistakes>
