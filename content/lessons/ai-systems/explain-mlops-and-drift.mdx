<Body>
## The two definitions, tight

- **MLOps** — "Getting models from notebook to production and keeping them healthy: reproducible training, experiment tracking, a model registry, reliable serving, monitoring, and retraining. It's DevOps plus the fact that data shifts and quality silently decays."
- **Drift** — "When production data moves away from training data. *Data drift* is the inputs changing distribution; *concept drift* is the input→output relationship changing. Both degrade accuracy with no code error."

## The lifecycle narrative

Train → track (MLflow) → register (versioned model) → serve (load once, behind an API) → monitor (latency, errors, drift) → retrain when warranted. Say it as a loop, not a list.

## The money question

*"How do you know your model is still good after deployment?"*

"I monitor it. Operationally — latency, error rate, throughput. Statistically — drift on inputs with KS/PSI, and on outputs or proxy metrics for concept drift. When drift crosses a threshold I investigate and, if warranted, retrain. I never assume a deployed model stays good."

## Connect to detection mechanics

Be ready to name KS test (continuous), PSI with the 0.1/0.25 thresholds, chi-squared (categorical), and embedding-distribution monitoring for LLM apps.
</Body>

"MLOps is getting models to production and keeping them healthy —
reproducible training, experiment tracking, a registry, serving,

data drifts and model quality decays even when the code is frozen.

I detect that with drift monitoring: data drift via KS test or PSI on

triggers investigation and, if warranted, retraining. So I'd never say a
model is 'done' at deployment — that's where the operational work begins."
