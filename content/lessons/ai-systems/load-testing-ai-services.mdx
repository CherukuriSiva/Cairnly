<Body>
## Why a single request lies

One request hits a warm cache, an idle CPU, no queueing. Production has dozens of concurrent requests competing for the same model and accelerator. Latency under load is a completely different number — and it's the only one that matters for capacity planning.

## Locust: traffic as code

Locust defines virtual users as Python tasks. You set how many users, how fast they ramp, and what mix of endpoints they hit. `@task(n)` weights make the mix realistic — e.g. mostly `/predict`, occasionally `/health`.

## Read the right metrics

- **p50 / p95 / p99 latency** — averages hide the tail; p95/p99 is what users feel.
- **RPS (throughput)** — requests/sec the service sustains.
- **Error rate** — timeouts and 5xx that appear *only* under load.
- **The knee** — ramp concurrency until latency spikes; that point is your real capacity per replica.

## Test the system, not just the box

Load-test through your load balancer with autoscaling enabled, so you also verify that scaling triggers *and* that new replicas warm up before they're handed traffic.
</Body>

<Code>
```python
from locust import HttpUser, task, between
import random

class InferenceTester(HttpUser):
    """Run: locust -f load_test.py --host=http://localhost:8000"""
    wait_time = between(0.1, 0.5)            # rapid, realistic pacing

    @task(3)                                # 3:1 weighting → mostly predictions
    def predict(self):
        features = [random.uniform(-3.0, 3.0) for _ in range(10)]
        with self.client.post("/predict", json={"features": features},
                              catch_response=True) as resp:
            if resp.elapsed.total_seconds() > 1.0:
                resp.failure("over SLA: >1s")   # flag latency-SLA breaches

    @task(1)
    def health(self):
        self.client.get("/health")
```
</Code>

<CommonMistakes>
- **Trusting single-request latency** — production concurrency tells a different story
- **Looking only at averages** — the p95/p99 tail is what users experience
- **Unrealistic traffic mix** — weight tasks to match real usage
- **Testing the box, not the system** — go through the load balancer with autoscaling on
- **No SLA assertion** — mark requests over your latency budget as failures
- **Ignoring warm-up** — cold replicas under sudden load skew results
</CommonMistakes>
