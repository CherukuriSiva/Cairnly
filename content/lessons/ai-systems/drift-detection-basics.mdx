Models rot. The inputs your model sees in month six look nothing like your training set, and accuracy quietly falls off a cliff with no error in the logs. Drift detection is the early-warning system that tells you to retrain *before* users notice. It's a core MLOps interview topic and a real production safeguard.

<Body>
## Two kinds of drift

- **Data drift (covariate shift)** — the *inputs* change distribution. Users start asking about topics your model never trained on. The relationship between input and output is unchanged; the inputs just moved.
- **Concept drift** — the *relationship* changes. The same input now maps to a different correct answer (a policy changed, fraud patterns evolved). Harder to detect because you often lack fresh labels.

## Detecting data drift

Compare a recent window of inputs to a reference (training) window:

- **KS test (Kolmogorov–Smirnov)** — for a continuous feature, tests whether two samples come from the same distribution. A small p-value = drift.
- **PSI (Population Stability Index)** — bins a feature and sums how much mass shifted between buckets. Rule of thumb: PSI < 0.1 stable, 0.1–0.25 moderate, > 0.25 significant drift.
- **Chi-squared** — for categorical features.

## Drift for LLM apps

You don't have tabular features, but you have **query embeddings**. Track the distribution of incoming query embeddings (e.g. cluster them, or PSI on a reduced dimension). A sudden shift means users are asking about new things your retrieval corpus may not cover.

## What an alert should do

Drift is a *signal*, not an automatic retrain. Route alerts to: collect fresh labels, expand the retrieval corpus, or schedule retraining — with a human deciding when the signal is strong enough.

<Code>
```python
import numpy as np
from scipy.stats import ks_2samp

def detect_data_drift(reference: np.ndarray, current: np.ndarray, alpha: float = 0.05) -> dict:
    """KS test per continuous feature; flags features whose distribution moved."""
    drifted = {}
    for i in range(reference.shape[1]):
        stat, p = ks_2samp(reference[:, i], current[:, i])
        drifted[f"feature_{i}"] = {"ks": float(stat), "p": float(p), "drift": p < alpha}
    return drifted

def psi(reference: np.ndarray, current: np.ndarray, bins: int = 10) -> float:
    """Population Stability Index between two 1-D samples."""
    edges = np.histogram_bin_edges(reference, bins=bins)
    ref = np.histogram(reference, edges)[0] / len(reference) + 1e-6
    cur = np.histogram(current, edges)[0] / len(current) + 1e-6
    return float(np.sum((cur - ref) * np.log(cur / ref)))
```

<CommonMistakes>
- **Confusing data and concept drift** — they need different responses
- **Auto-retraining on every alert** — drift is a signal; a human decides
- **No reference window** — you need a fixed baseline to compare against
- **Watching only inputs** — concept drift needs label/outcome monitoring too
- **PSI without sensible bins** — too few/many bins distorts the index
</CommonMistakes>
